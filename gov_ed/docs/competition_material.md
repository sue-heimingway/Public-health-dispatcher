# 参赛材料 · 词元工厂（社会治理与企业服务赛道）

> 底层资产：急诊分诊多智能体系统（6 Agent + Human-in-the-loop）
> 平移目标：突发公共卫生事件与民生医疗诉求处理

---

## 一、项目名称（融合版：民声的暖 + 词元的刃）

**主推：民声先知 · 词元引擎**（Token Foresight）
取义：主名「民声先知」扛起民生温度，"词元引擎"点明技术底座（词元工厂）。
一个名字同时回答两个问题——"你叫什么"（民声先知）与"你靠什么技术"（词元引擎）。

**备选 1：词元 · 民声先知**
取义：把"词元"前置绑定大赛 IP，"民声先知"托底，辨识度更高、略偏技术。

**备选 2：先知民声**（TokenVoice）
取义："先知"动词化 = 提前听见人民的声音；英文 TokenVoice 同时含 token + voice，极简有温度。

> 融合逻辑：B 的「词元」是抓手，A 的「民声先知」是灵魂——
> 把"词元"降级为技术背书，把"民声/先知"升为项目主张，一个都不丢。
> 配套 Slogan 天然对仗：「让每一条民声，都跑在危机前面。」（民声先知 = 民声先知）

## 三、项目痛点

**痛点一：话务海啸，救命信息被稀释。**
突发公共卫生事件一旦发生，12345 热线与卫健委话务量数十倍暴涨，接线员被海量重复的
"买不到药""老人发烧""什么时候解封"淹没——真正危及生命的求助，和普通咨询混在同一条河里，
谁也分不出哪一条是"几分钟内要死人"的。

**痛点二：研判迟缓，黄金窗口被错过。**
聚集性疫情、断药潮、恐慌抢购、群体性事件，往往先以零散、口语化的只言片语散落在
电话录音和留言里。靠人工逐条翻阅，等研判出"这是一起聚集性苗头"时，
最佳处置窗口早已关闭，小事拖成大事、个案拖成舆情。

**痛点三：机械回复，救助者变成上访者。**
面对极其恐慌、愤怒、绝望的群众，一句"请耐心等待""按流程处理"就是舆情引爆点。
缺乏情绪识别与话术约束的自动回复，正在把"求助"二次加工成"次生舆情"。

**痛点四：转办靠手，处置缺闭环。**
多部门转办依赖人工电话与经验，没有统一的分级标准、没有自动升级机制、没有全程留痕，
高危诉求可能被当成普通工单漏办，事后也追不到责任。

## 四、解决方案：六大 Agent 重塑（无缝平移）

> 核心叙事：**急诊分诊是"救一个病人"，社会治理是"救一个群体的危机"——
> 同一套 Multi-Agent 框架，两个战场。** 底层逻辑完全一致：采集→排雷→定级→质控→追踪→沟通。
>
> 技术定位（对齐"词元工厂"大模型主题）：**大模型做理解，规则做兜底，人做决策。**
> 大模型负责诉求抽取、情绪识别、通报话术生成；规则引擎负责四级分级、风险排雷、质控安全底线；
> 无 API、断网、超时一律自动降级纯规则，主流程永不中断。

| # | 急诊版 | 社会治理版（新命名） | 一句话职责 |
|---|---|---|---|
| ① | 信息采集 Agent | **民声精译官** | 把杂乱口语译成标准诉求，自动抓地址/人数/情绪 |
| ② | 红旗预警 Agent | **风险哨兵** | 从海量民声中揪出聚集疫情、断药潮、恐慌、群体苗头 |
| ③ | 分级裁判 Agent | **响应定级官** | 四级政务响应：一级转120/110，二级转网信/宣传，三级派单，四级自动答复 |
| ④ | 交叉核验质控 Agent | **次生舆情守门员** | 防误判、防冷回复、防"机械答复"引爆舆情 |
| ⑤ | 动态监测 Agent | **民声热源追踪** | 多人跟帖"我们也这样"→ 自动重新评估并升级 |
| ⑥ | 沟通安抚 Agent | **政务安抚通报官** | 生成官方、有人情味、不失原则的通报，一键推送 |

外加底层：**Human-in-the-loop 强制接管**——高危、Agent 分歧、舆情升级时，弹窗呼叫值班人员，
人工裁决留痕，Agent 只自动升级、绝不自动降级。

### ① 民声精译官（原：信息采集 Agent）
把市民的白话翻译成标准诉求标签："救命啊买不到退烧药"→【药品短缺】，
"我家老人发烧喘不上气"→【重症就医求助】；同时自动抽取**地址、涉及人数、情绪强度**，
省去人工二次录入。急诊版翻译的是"症状"，这里翻译的是"民生"。

### ② 风险哨兵（原：红旗预警 Agent）
内置 10 类社会高危风险规则，每条都带"为什么高危 / 时效 / 补问清单 / 处置动作"：
传染病聚集性爆发、群体食物中毒、校园安全隐患、群体性事件苗头、谣言恐慌传播、
独居老人急难、物资药品抢购、欠薪聚集讨薪、危及生命安全的紧急救助、次生舆情风险。
就像急诊版"宁可错杀不可放过漏诊"，这里"宁可多报不可放过一起群体性风险"。

### ③ 响应定级官（原：分级裁判 Agent）
把 ESI 四步法平移到"政务四级响应"：
**一级**危及生命/安全 → 转 120/110/119 + 属地立即到场；
**二级**恐慌/舆情/群体苗头 → 转宣传部/网信办/政法；
**三级**具体诉求 → 派发责任部门工单限时办理；
**四级**政策咨询 → 自动答复闭环。
每条诉求都有明确的处置通道、响应时限、队列位次。

### ④ 次生舆情守门员（原：交叉核验质控 Agent）
急诊版防"漏诊、给错级"，这里防"误判、次生舆情"。用独立的安全底线卡裁判：
任何生命/安全风险不得低于一级，任何舆情/群体风险不得低于二级；
更关键的是——**当市民情绪极其恐慌/愤怒/绝望时，直接拦截"请耐心等待"式的自动答复，
强制升级为温和的人工回应**。这是本项目与普通"智能客服"最本质的区别。

### ⑤ 民声热源追踪（原：动态监测 Agent）
急诊版让患者扫码说"更痛了"，这里监控"诉求热度"：当某个求助帖出现"我们小区也这样"的
多人跟帖、或诉求人反馈"更紧急了""有人传谣"，系统自动重新跑一遍②③④并提升响应等级，
把"舆情热点"实时翻译成"处置优先级"。

### ⑥ 政务安抚通报官（原：沟通安抚 Agent）
为每条诉求自动生成四版通报（常规/安抚/降温/兜底），内嵌措辞禁忌：
不承诺"立即解决"、不点名不泄露隐私、不推诿、不传播未经核实信息。
既安抚了当事人，又守住了政务边界——把"有可能上热搜的那句话"提前换成"有温度的那句话"。
